# 技能自进化协议（总指挥执行）

本文件定义技能包自身的**自进化机制**：提示词触发、按轮次参数执行，
每轮含自我评审与硬门禁。自进化是总指挥的**元任务**（治理技能包自身），
**不走项目六阶段流水线**；本任务不适用"总指挥不代替子角色产出"红线
（该红线约束项目任务；元任务的产出以本协议第 5 节评审清单为门禁）。

## 1. 触发与参数

用户 prompt 显式命中 `自进化` / `自我进化` / `自我评审` / `skill evolve` /
`evolve skill`，**且对象是本技能包自身**。可选参数（缺省值括号内）：

| 参数 | 形态 | 取值 |
|---|---|---|
| 轮次 | `N轮` / `N rounds` | 1-5（默认 1；>5 拒绝执行并说明上下文膨胀风险，建议分会话） |
| 焦点 | `焦点=<域>` | 知识库 / 宪法与协议 / 角色契约 / 模板 / evals / 全包（默认 全包） |
| 模式 | `模式=<m>` | 评审（默认）/ 沉淀 / 横向 / 纵向（可多选，如 `模式=评审+沉淀`） |

示例：`自进化 2轮 焦点=知识库`、`自进化 模式=横向`、`自进化 3轮 焦点=模板 模式=纵向`。

**误触发防护**：普通项目任务中的"优化/改进/评审/进化"字样不触发本协议——
仅当目标明确是技能包自身（完善/评审/进化本 skill、知识库、角色、协议）才进入。

## 2. 模式定义

| 模式 | 做什么 | 产出方向 |
|---|---|---|
| 评审 | 对照第 5 节评审清单按焦点扫描，发现问题直接修复 | 既有文件修复 + 教训沉淀入 `knowledge/` |
| 沉淀 | 把会话内任务经验与历史版本教训提炼为知识条目 | `knowledge/lessons.md` 增量 |
| 横向 | 新增知识域：新栈规范 / 新站点类型模式 / 新模板 / 新角色 | 新文件（骨架先立、成熟度=草稿，后续轮次纵向深化） |
| 纵向 | 深化既有知识文件：补正反例 / 失败分支 / 反模式 | 既有文件增量（不另立副本） |

## 3. 每轮流程（探测 → 提案 → 自我评审 → 落盘 → 报告）

1. **探测**：按焦点扫描——evals 覆盖缺口、FILES.md 与磁盘双向一致性、
   引用闭环（被引用路径/字段/编号全部存在）、版本一致性（SKILL.md metadata /
   README / evals.json 三处同版本）、知识盲区（声明了却为空 / 存在却未声明）。
   探测聚焦焦点范围，不做全包无锚点漫游。
2. **提案**：逐条产出提案，每条必含——目标文件、变更内容、**级别**（L1/L2/L3，
   见第 4 节）、**来源**（任务沉淀 / 评审发现(轮次) / 用户反馈(原话) /
   官方文档(出处)）、影响面（受牵连文件与 evals）。
   **域知识提案**（某栈/某角色/某站点类型的专业内容）须征询对应角色视角校对
   （模式 A 委派 / 模式 B 换装），总指挥不凭空裁定域知识正误。
3. **自我评审**：全部提案过第 5 节评审清单；不通过的提案打回修改，
   每条最多打回 2 次，第 3 次留档为"未采纳 + 理由"（计入本轮报告的提案池，下轮可重提）。
4. **落盘**：通过的提案写入目标文件 + `FILES.md` 同步 + evals 增量（只增不减）+
   版本号唯一来源 `SKILL.md` metadata（递增幅度与变更性质匹配：评审修复/缺陷修复 =
   patch，新增能力或知识域 = minor；同一自进化会话只定版一次，会话内多轮不重复递增）+
   `README.md` 版本记录逐轮留痕（评审发现/沉淀条目编号/采纳与未采纳清单）。
5. **报告**：按 `templates/evolution-report.md` 模板输出本轮进化摘要——采纳 n / 提案 m、
   改动文件清单、知识条目增量、未采纳提案及理由、软门禁放行留痕、下轮建议焦点；
   会话内交付，不归档进技能包。

## 4. 知识分级与准入（不同程度的规则）

| 级别 | 含义 | 典型载体 | 变更约束 |
|---|---|---|---|
| L1 强制 | 违反即失败 | 宪法条款、角色红线、质量门禁、评审清单硬门禁 | 用户显式批准才可变更 |
| L2 推荐 | 偏离须留痕说明理由 | 协议规则、最佳实践 | 自进化可改，评审清单通过即落盘 |
| L3 参考 | 按场景取用，不强制 | 正反参考、可选参考、模式参照、经验教训 | 同 L2 |

准入门槛（**不发明知识**）：每条知识必须挂来源；无来源的记入提案池
标注"待验证"，不落盘。正反参考类条目（L3）必须给正例或反例至少其一，
反例须含**后果与修正**。条目格式见 `knowledge/README.md`。

## 5. 自我评审清单（每条提案逐项过）

| # | 检查项 | 判定 |
|---|---|---|
| 1 | 来源真实可溯：任务沉淀 / 评审发现(轮次) / 用户反馈(原话) / 官方文档(出处) | 硬门禁 |
| 2 | 单一真值源：新知识写入既有真值源文件，不另立副本、不重复既有条目 | 硬门禁 |
| 3 | 宪法兼容：不与宪法 29 条冲突；涉宪法/红线/L1 变更已获用户显式批准 | 硬门禁 |
| 4 | evals 回归：既有用例全部仍通过；新能力/新协议有对应用例 | 硬门禁 |
| 5 | 引用闭环：新增引用的路径/字段/编号在真值源中已定义；FILES.md 与磁盘双向同步 | 硬门禁 |
| 6 | 版本纪律：版本号唯一来源 SKILL.md metadata；README 版本记录已留痕；历史版本记录不重写 | 硬门禁 |
| 7 | 级别声明且与内容强度匹配：规则不虚标 L1，参考不冒充强制 | 硬门禁 |
| 8 | 正反例完整（L3 条目）；失败分支画全（流程/交互类提案）；成熟度标注（横向新域=草稿） | 软门禁 |

任一硬门禁不通过即打回；软门禁不通过可附理由放行（报告中留痕）。

## 6. 宪法与 evals 保护（不可静默进化面）

- **宪法条目增删改**：自进化只能**提案**，用户显式批准后才可落盘；未批准留档提案池。
- **evals 用例删除或弱化**：同样须用户批准；新增不设限。
- **README 版本历史只增不改**：已发布版本的记录不重写（修正历史以新条目补充说明）。

## 7. 上下文预算与红线

- 单轮改动文件数原则上 ≤12（横向新域骨架除外）；超出则拆到下一轮。
- 模式 B（无 subagent）下建议轮次 ≤2，防止上下文膨胀失焦；用户坚持时如实提示风险后执行。
- 不为"进化"而进化：无可采纳提案的轮次如实输出"本轮零变更"，不制造无效 diff。
- 提案池不落盘未验证知识；升级到 L2 须 ≥3 个不同任务验证（见 knowledge/README.md 升级规则）。
