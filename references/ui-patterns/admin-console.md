# UI 模式：后台管理（admin-console）

> 站点类型模式之一：由 `agents/ui-ux-designer.md` 站点类型路由加载。
> 本文件定**设计侧**要求：描述行为与外观，不绑定具体 UI 库组件名（设计师红线）。
> 通用要求（五态、四全局态、4.5:1 对比度、44px 点击区）见 `templates/ui-spec.md`，不重复。
> 实现层由管理后台双角色承载（路由规则见 `references/orchestration.md`
> 管理后台路由规则；实现规范见 `references/standards/frontend-antd.md`），
> 与本文件互链不重复。

## 1. 适用信号

需求命中"管理后台/中后台/admin/运营平台/控制台"（识别信号同管理后台双角色）；
用户是**内部运营/管理人员**，核心诉求是效率与防错，不是浏览体验。

## 2. 设计目标与用户心智

- **效率优先**：高频任务路径最短（筛选 → 定位 → 操作，全程不换页最好）。
- **信息密度**可调：专业用户容忍高密度，密度高于 C 端但层级不乱。
- **防误操作**：破坏性操作必须可确认、可感知影响范围、尽量可撤销。

## 3. 页面清单（IA 模板）

| 页面 | 必备性 | 核心区块 |
|---|---|---|
| 登录 | 必备 | 账号密码 + 验证码/二次校验；错误反馈不泄露"账号是否存在" |
| 框架布局 | 必备 | 侧栏菜单（权限驱动显隐，可折叠）+ 顶栏（用户/退出）+ 面包屑 + 标签页/多页签（可选） |
| 工作台 | 常备 | 待办 + 关键指标卡 + 快捷入口 |
| 列表页（CRUD 三件套之一） | 必备 | 筛选区 + 数据表格（服务端分页/筛选/排序）+ 批量操作 + 新建入口 |
| 表单页（新建/编辑复用） | 必备 | 分组/分步长表单 + 字段校验 + 草稿（如契约支持） |
| 详情页 | 必备 | 概要头 + 分组信息 + 关联操作；轻查看用抽屉，复杂编辑用独立页 |
| 配置页 | 常备 | 表单化配置 + 保存前变更提示 |
| 结果反馈页 | 必备 | 403（无权限 + 原因）/ 404 / 500 |

## 4. 列表页模式（类型核心页）

- 筛选区：常用筛选 ≤5 项常驻，高级筛选折叠；已选条件可单独移除。
- 表格：列宽可调、操作列固定、行内操作不换行；枚举/状态列用色彩 + 文字双编码
  （不只靠颜色，可达性硬约束）；金额/时间格式全表统一。
- 空数据态给"新建/调整筛选"引导，不是一句"暂无数据"。
- 加载态不整页白屏（骨架或局部加载）；查询竞态由前端处理（设计上要求切页不闪旧数据）。

## 5. 关键交互流与失败分支

- **查-改流**：筛选 → 定位行 → 进编辑 → 保存反馈 → 列表局部刷新；
  失败分支：保存冲突（他人已改，给对比/覆盖选择）、校验失败（定位到字段）。
- **批量操作流**：选择计数常驻 → 确认框列明影响范围（"将影响 N 条"）→
  执行中进度可见 → 完成展示逐条结果（成功 n / 失败 m + 失败原因 + 重试入口）。
- **破坏性单条操作**：红色视觉 + 明确后果文案；高危操作（删除、清空、改价）
  要求二次确认，超高危可要求输入确认词。
- **导入导出流**：导入模板下载 + 校验错误行报告（可下载）；导出异步化时
  给进度与完成通知（大导出不允许页面假死等待）。

## 6. 类型专属组件模式

筛选区、数据表格、抽屉（轻查看/快捷编辑）、分步表单、操作确认框、
批量结果反馈、权限占位（无权限渲染禁用态 + 原因提示，而非纯隐藏——
前端隐藏不是安全，宪法第 9 条）。所有交互组件五态齐全（通用要求）。

## 7. 视觉与布局基调

- 中性色主导，语义色只用于状态与操作级别；正文 12-14px，密度优先于留白。
- 键盘可达：Tab 顺序合理、回车提交查询/表单、Esc 关闭弹层（高频操作者依赖键盘）。
- 响应式：桌面优先（≥1280px），最小可用即可，不做移动端过度适配（与管理端实现约定一致）。
- 弹层不套弹层超过两层；批量操作结果不用一个"成功"toast 概括。

## 8. 信任与合规要点

- 权限态如实呈现：按钮级权限码映射由设计侧标注（页面 ↔ 权限码清单交给
  admin-backend-dev 对齐）。
- 审计敏感操作：设计上让操作者清楚"此操作会被记录"（如文案注明），不偷记。
- 列表筛选字段与契约筛选白名单一一对应，不发明契约外筛选项。

## 9. 度量建议

高频任务完成步数（筛选→定位→操作点击数）、批量操作失败率、
查询到详情平均时长（设计侧只建议埋点位置，不定义指标口径）。

## 10. 反模式（红线）

- 破坏性操作无确认、不可撤销、确认框不写影响范围。
- 全量拉取前端分页（设计上注明数据量预期，引导服务端分页）。
- 弹窗套弹窗两层以上；保存失败不定位字段。
- 首页堆砌装饰性图表却没有待办与快捷入口（工作台为效率服务）。
