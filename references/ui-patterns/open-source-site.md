# UI 模式：开源项目官网（open-source-site）

> 站点类型模式之一：由 `agents/ui-ux-designer.md` 站点类型路由加载。
> 本文件只定**类型专属**要求；通用要求（五态、四全局态、4.5:1 对比度、44px 点击区）
> 见 `templates/ui-spec.md`，不重复。

## 1. 适用信号

需求主体是开源项目（GitHub/Gitee 仓库托管）；目标受众是**开发者**；
站点核心是"是什么 + 怎么装 + 怎么用 + 怎么参与贡献"，不是营销转化。

## 2. 设计目标与用户心智

- 开发者 5 分钟内走完：知道是什么 → 复制安装命令 → 跑通 Hello World。
- 可信度可视化：维护活跃度（最近提交/发布节奏）、CI 状态、社区规模。
- 双受众分流：使用者（文档/示例）与贡献者（贡献指南/架构说明/路线图）。

## 3. 页面清单（IA 模板）

| 页面 | 必备性 | 核心区块 |
|---|---|---|
| 首页 | 必备 | 首屏公式 + 核心特性 + 快速开始摘要 + 生态/社区入口 |
| 快速开始（Getting Started） | 必备 | 环境要求 + 安装（多包管理器）+ 最小可运行示例 + 常见安装问题 |
| 文档 | 必备 | 独立 docs 站或子站：目录树 + 全文搜索 + 版本切换 |
| API 参考 | 常备 | 链接到生成文档或独立页 |
| 示例/演示 | 常备 | 可运行示例清单 / 在线演示链接 |
| 生态 | 常备 | 插件、集成、相关项目、依赖它的项目 |
| 社区 | 常备 | Issue / Discussion / 聊天群 / 论坛入口 + 行为准则 |
| 贡献指南 | 常备 | 如何提 Issue/PR、开发环境搭建、代码规范链接 |
| 博客/路线图 | 可选 | 版本计划、设计文章 |
| 赞助 | 可选 | 赞助渠道 + 赞助商鸣谢 |

## 4. 首屏公式

项目名 + 一句话定位（≤12 字，"xx 是一个用于 xx 的 xx"）+
安装命令代码块（带复制按钮，多包管理器切换）+
徽章行（CI 状态 / 最新版本 / License / Star 数）+
快速上手入口（唯一主 CTA）+ 核心特性 3-6 条（每条一行，一句话）。

## 5. 关键交互流与失败分支

- **安装→Hello World 流**（核心任务）：全程可复制粘贴，不允许"截图贴代码"；
  代码块支持多语言/多系统/多包管理器切换（切换后复制按钮作用于当前块）；
  版本切换器与文档版本联动，旧版本文档显著标注"非最新"。
- **文档搜索流**：全文搜索带结果高亮；无结果给相近结果与"提 Issue"出口。
- **贡献引导流**：从"我想帮忙"到第一次 PR 的路径在贡献指南内一页走通，不层层跳转。

## 6. 类型专属组件

代码块（语法高亮 + 复制 + 多 tab 切换 + 文件名/路径标注）、状态徽章（CI/版本/
License/Star，链接到真实源）、特性网格、贡献者头像列表、版本发布时间线、
文档目录树 + 阅读进度指示。所有交互组件五态齐全（通用要求）。

## 7. 视觉与布局基调

- 极简：营销动效最小化，文档可读性优先——正文 ≥16px、行高 1.6-1.8、
  正文行宽 ≤70 字符（中文 ≤38 字）、代码字体与正文字体区分。
- **暗色模式为标配**（开发者习惯），明暗两套对比度均达 4.5:1。
- 文档站与主页视觉一体（同色板同字体），不做成两个割裂的站点。

## 8. 信任与合规要点

- License 明示且与仓库 LICENSE 文件一致。
- 维护状态透明：不掩饰低维护状态；归档项目显著标注"不再维护"。
- 安全披露渠道可见（SECURITY.md 链接）；贡献条款（CLA/DCO）如有须在贡献指南声明。

## 9. 度量建议

安装命令复制次数、快速开始页到达与完成停留、文档搜索无结果率、
GitHub/Gitee 入口点击率（设计侧只建议埋点位置，不定义指标口径）。

## 10. 反模式（红线）

- 首页营销化吹嘘却没有一行可复制的代码。
- 文档只有 API 罗列、没有 Getting Started（新手第一道墙）。
- 安装步骤要翻三页；代码块无复制按钮；文档只有英文却宣称支持中文用户。
- 主页宣称的版本/特性与仓库实际状态不符（宁可少写不可写错）。
